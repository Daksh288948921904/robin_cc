# robin cc — News Intelligence Dashboard

[![Python 3.11+](https://img.shields.io/badge/python-3.11+-blue.svg)](https://www.python.org/downloads/)
[![Flask](https://img.shields.io/badge/flask-3.x-green.svg)](https://flask.palletsprojects.com/)
[![Platform](https://img.shields.io/badge/platform-Windows%20%7C%20macOS%20%7C%20Linux-lightgrey)](https://github.com/Jkavya100/osi-news-automation)

A news intelligence system that aggregates headlines from 70+ RSS sources, clusters stories across outlets, and enriches each article with AI synthesis, event timelines, and live social media reactions.

**Live dashboard → `http://localhost:5001`**

---

## What it does

Open an article in the reader panel and you get:

| Section | Description |
|---------|-------------|
| **Media Coverage** | Other outlets reporting the same story (similarity search) |
| **AI Synthesis** | Multi-source article draft generated by Groq LLM |
| **Event Timeline** | Chronological breakdown of events |
| **Netizens Reaction on Twitter** | Live tweets + AI reaction summary (Apify) |
| **Netizens Reaction on Instagram** | Live IG posts + AI reaction summary (Apify) |

All sections are inline-editable and the AI synthesis can be downloaded as a `.docx`.

## Setup

### 1. Clone and enter the project

```bash
git clone https://github.com/Jkavya100/osi-news-automation.git
cd osi-news-automation
```

### 2. Create a virtual environment

**macOS / Linux:**
```bash
python3 -m venv venv
source venv/bin/activate
pip install --upgrade pip
```

**Windows:**
```bash
python -m venv venv
venv\Scripts\activate
python -m pip install --upgrade pip
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

> **Apple Silicon (M1/M2/M3) note:** if `torch` fails, run:
> ```bash
> pip install torch torchvision torchaudio
> pip install --upgrade accelerate
> ```

### 4. Start MongoDB

**macOS (Homebrew):**
```bash
brew tap mongodb/brew
brew install mongodb-community
brew services start mongodb-community
```

**Windows:** Download and run the installer from [mongodb.com](https://www.mongodb.com/try/download/community). It installs as a service automatically.

**Linux (Ubuntu/Debian):**
```bash
sudo apt-get install -y mongodb-org
sudo systemctl start mongod && sudo systemctl enable mongod
```

### 5. Configure environment variables

Create your `.env` file by copying the template and filling in your keys:

```bash
cp .env .env.backup   # keep a reference copy
```

Then edit `.env` — the minimum set of variables you need:

```env
# --- REQUIRED ---

# Groq LLM (AI synthesis, timelines, social summaries)
GROQ_API_KEY=gsk_your_key_here

# Apify (Twitter + Instagram scraping)
APIFY_API_TOKEN=apify_api_your_token_here

# MongoDB
MONGODB_LOCAL_URI=mongodb://localhost:27017/
MONGODB_DATABASE=osi_news_automation

# --- OPTIONAL but recommended ---

# Guardian (adds ~200 extra articles per fetch)
GUARDIAN_API_KEY=your_guardian_key

# Cloudinary (image hosting for CMS publishing)
CLOUDINARY_CLOUD_NAME=your_cloud_name
CLOUDINARY_API_KEY=your_api_key
CLOUDINARY_API_SECRET=your_api_secret

# Hocalwire CMS (only needed if publishing articles)
HOCALWIRE_API_KEY=your_hocalwire_key
HOCALWIRE_API_URL=https://democracynewslive.com/dev/h-api/createFeedV2
```

> You can run multiple Groq keys (`GROQ_API_KEY_2`, `GROQ_API_KEY_3`, … `GROQ_API_KEY_7`) — the system rotates them automatically on rate limits.

### 6. Verify database connection

```bash
python3 -c "from src.database.mongo_client import get_client; print('DB OK:', get_client())"
```

## Running the dashboard

```bash
python3 src/frontend/app.py
```

Open **http://localhost:5001** in your browser.

**Quick start flow:**
1. Click **Fetch Latest** in the sidebar — waits ~20–30 s while it scrapes 70+ RSS feeds
2. Click any article card to open the reader panel
3. Media Coverage loads immediately; AI Synthesis, Timeline, and Social Reactions load in parallel (allow 1–3 min for Apify)
4. Click **{ } Raw JSON** at the bottom of the reader to inspect the raw data
5. Click **Download .docx** to export the AI-synthesised article

## API endpoints

All endpoints are served on `http://localhost:5001`.

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/` | Main dashboard UI |
| `GET` | `/api/articles` | List all loaded articles |
| `GET` | `/api/articles/<idx>` | Single article by index |
| `POST` | `/api/scrape` | Start background RSS fetch |
| `GET` | `/api/scrape/status` | Poll scrape progress |
| `POST` | `/api/save` | Save current articles to JSON |
| `POST` | `/api/load` | Load articles from latest JSON file |
| `GET` | `/api/articles/<idx>/coverage` | Cross-outlet coverage for an article |
| `POST` | `/api/articles/<idx>/summary` | Generate AI multi-source synthesis |
| `POST` | `/api/articles/<idx>/timeline` | Generate event timeline |
| `POST` | `/api/articles/<idx>/social` | Scrape Twitter + Instagram reactions |
| `POST` | `/api/articles/<idx>/download` | Download synthesis as `.docx` |

## Troubleshooting

### `python` not found on macOS/Linux
Always use `python3` and `pip3`:
```bash
python3 src/frontend/app.py
```

### MongoDB connection refused
```bash
# macOS
brew services start mongodb-community

# Linux
sudo systemctl start mongod

# Windows — open Services and start "MongoDB"
```

### Groq rate limit errors
Add more keys to `.env` as `GROQ_API_KEY_2`, `GROQ_API_KEY_3`, etc. The system rotates them automatically.

### Social reactions not appearing
- Apify scrapes run for ~1–2 minutes. Wait for the spinners to finish.
- Check your `APIFY_API_TOKEN` is set in `.env`.
- Twitter uses actor `gentle_cloud~twitter-tweets-scraper`; Instagram uses `apify~instagram-hashtag-scraper`.

### Module import errors
```bash
# Make sure the venv is activated — you should see (venv) in your prompt
pip install --upgrade -r requirements.txt
```

### Port 5001 already in use
```bash
# Find and kill the process using that port
lsof -ti:5001 | xargs kill -9   # macOS/Linux
```

## Running the full automation pipeline

The dashboard is the main interface, but the full pipeline (scrape → cluster → generate → publish) can be run separately:

```bash
# Run once immediately
python3 run_automation.py --mode once

# Run on a schedule (every N hours as set in .env)
python3 run_automation.py --mode scheduled

# Dry run — no uploads
python3 run_automation.py --mode dry-run
```
